# UX этап 3: консистентность и демо-лоск

**Дата:** 2026-07-04
**Статус:** дизайн согласован, ждёт ревью спеки
**Родитель:** [2026-07-02-ux-roadmap-design.md](2026-07-02-ux-roadmap-design.md) §5 (этап 3 из четырёх).
**Скоуп:** единый табличный язык, политика фидбека, адаптивный минимум, хелпер
плюрализации, персист аномалий структуры. Без редизайна и новых фич.

## 1. Контекст: что показал аудит (main после PR #20–#23)

Табличные поверхности разошлись на **два лагеря**:

| Поверхность | Примитив | Стиль шапки |
|---|---|---|
| `EstimateList`, `StructureNotice` | shadcn `Table` | дефолт: обычный регистр, `h-10 font-medium`, `p-2`, hover у всех строк |
| `ArticleTable` | сырой `<table>` | DS: `uppercase text-xs` на `--ds-surface-sunken`, `px-4 py-2.5`, `--ds-hairline`, без hover |
| `ReviewGrid` (этап 2) | div-grid (виртуализация) | DS — литералы скопированы из `ArticleTable` |
| `ContextStrip` | flex-полоса | DS-литералы, своя копия |

Фидбек: логин показывает ошибку аутентификации toast-ом при инлайн-валидации
полей той же формы; тумблер фонда при 0 промоутабельных строк «отщёлкивается»
с `toast.info`; ошибка загрузки списка смет — голый `<p>`, а сметы — `Alert`.
Адаптив: у `ArticleTable` нет `overflow-x`, `1fr`-колонки `ReviewGrid`
сжимаются в кашу, `AppShell` без единого responsive-класса. Плюрализация —
одна локальная `pluralizeZamechanie` + «строк(ах)» и фиксированные формы.
Аномалии структуры живут только в navigate-state → теряются при F5 и по
прямой ссылке (осознанное ограничение Task 7 этапа 1, закрываемое здесь).

## 2. Ключевые решения (и почему)

| Решение | Обоснование |
|---|---|
| Канон — DS-стиль (uppercase-шапка на sunken, `px-4`, hairline), не shadcn-дефолт | Этап 2 уже закрепил его в главном экране (ReviewGrid); переделок меньше, стиль — «свой» язык MR DS. |
| Общий модуль `ds-table.tsx`: обёртки над shadcn-примитивами + экспорт строковых констант | Один источник стиля по построению — дрейф невозможен. Вендорный `ui/table.tsx` не правится (shadcn-first). Констант достаточно для div-поверхностей (ReviewGrid, ContextStrip) — их разметка не ломается. Отвергнуты: правка классов на местах (так и возник раскол) и TanStack DataTable (овекилл для четырёх непохожих таблиц). |
| `interactive` следует кликабельности **строки**, не поверхности | Hover+cursor на некликабельном — ложный аффорданс. В `ReviewGrid` — от вычисленного `clickable` (excluded/pending и read-only-режим — без hover), в `EstimateList` — `status !== "blocked"`. |
| Политика фидбека — четыре ножки (см. §4) | Валидация/исходы/ошибки загрузки/процесс загрузки покрывают все сегодняшние случаи; каждая ножка уже имеет прецедент в коде — политика фиксирует лучший из них. |
| Root-ошибка логина рендерится вручную | shadcn `FormMessage` привязан к полю через `FormField`-контекст и ошибку `root` сам не показывает — без явного указания воркер получит молча-не-показывающуюся ошибку. |
| Тумблер фонда: `promotableCount` — полное зеркало серверного предиката | Клиентский `matched` (по `decisionFor`) не годится в обе стороны: `initReview` даёт `kind: "confirmed"` авто-уверенным строкам без решения оператора (ложно-активный тумблер), а анти-накрутка фонда исключает подтверждённые фонд-хиты (ложно-«есть что промоутить»). Зеркалим `_PROMOTABLE_REVIEW` + анти-накрутку с перекрёстными комментариями — паттерн `REVIEWABLE ↔ _REVIEWABLE` уже дважды оправдался. |
| Аномалии — две колонки в `estimates`, запись в ingest | Парсинг синхронный внутри `POST /estimates` (`service.ingest`, routes/estimates.py) — аномалии известны в той же транзакции, что смета и строки. Отдельная таблица не нужна: данные read-only, показываются целиком. |
| Фронт читает аномалии из первичного `GET`, ре-фетч не нужен | `EstimatePage.load()` всегда делает `GET` на маунте — у свежезагруженной сметы аномалии уже в БД (парсинг завершился в POST). Notice хранится в state компонента и переживает переход processing→open. Каналы navigate-state и ответа полла не нужны. |
| Playwright как инфраструктура проекта НЕ заводится | Живые гейты — браузер с эмуляцией ширины (DevTools / браузерный инструментарий агента, как на гейтах PR-B). Решение об e2e-инфраструктуре — вне этапа. |
| Шапка: компактный режим, не гамбургер | Два таба влезают и в 480px; гамбургер — лишний клик и механика для мобильной версии, которая вне скоупа (§7 роадмапа). |
| Магическая высота `h-[calc(100vh-184px)]` не трогается | Компактный режим меняет только горизонтальные отступы — высота шапки прежняя. Уходит в TECH_DEBT. |

## 3. Единый табличный язык

Новый модуль `frontend/src/components/common/ds-table.tsx` — единственный
источник табличного стиля:

- **Обёртки** `DsTable` / `DsTableHeader` / `DsTableBody` / `DsTableRow` /
  `DsTableHead` / `DsTableCell` — реэкспорт shadcn-примитивов из `ui/table.tsx`
  с зашитыми через `cn()` классами. Канон:
  - шапка: ряд на `bg-[var(--ds-surface-sunken)]`; ячейки шапки
    `px-4 py-2.5 text-xs font-normal tracking-wide uppercase text-muted-foreground`;
  - ячейки: `px-4 py-2 text-sm`;
  - бордеры: `border-[var(--ds-hairline)]`;
  - hover-подсветки по умолчанию НЕТ.
- **`DsTableRow` принимает проп `interactive?: boolean`** →
  `hover:bg-muted/50 cursor-pointer`. Правило: `interactive` = кликабельность
  конкретной строки (не поверхности).
- **Экспорт констант** `dsHeadCellClass` / `dsCellClass` / `dsHairline` — для
  поверхностей, которые не могут быть `<table>`.

Миграция потребителей:

| Компонент | Было | Станет |
|---|---|---|
| `ArticleTable` | сырой `<table>` | `DsTable*`; бесплатно получает `overflow-x-auto` из shadcn Table; древовидный отступ inline-стилем остаётся |
| `EstimateList` | shadcn-дефолт | `DsTable*`; `interactive` на строках со `status !== "blocked"` |
| `StructureNotice` | shadcn-дефолт | `DsTable*` |
| `ReviewGrid` | div-grid, свои литералы | классы из констант; hover — от вычисленного `clickable` |
| `ContextStrip` | flex-полоса, свои литералы | константы из модуля |

Семантика не меняется: shadcn Table рендерит настоящий `<table>`, `ReviewGrid`
сохраняет `role="table"` — существующие тесты по ролям остаются валидными.

## 4. Политика фидбека (правило проекта)

1. **Валидация форм** → инлайн `FormMessage` у поля.
2. **Исходы асинхронных действий** (сохранение, удаление, импорт, экспорт) → toast.
3. **Ошибки загрузки данных** → инлайн `Alert variant="destructive"` в области
   контента, не toast (страница без данных + исчезнувший тост — тупик).
4. **Процесс загрузки данных** → skeleton в области контента, не спиннер и не
   пустой рендер.

Изменения этапа:

- **Логин** (`LoginScreen`): ошибка аутентификации переезжает из toast в инлайн —
  `form.setError("root", { message })`; рендер вручную:
  `<p className="text-sm text-destructive" role="alert">` из
  `form.formState.errors.root?.message` под кнопкой (`FormMessage` root не
  показывает). Сброс root-ошибки при следующем сабмите. Toast удаляется.
- **Тумблер фонда** (`DoneScreen`): хелпер `promotableCount(rows)` в
  `lib/reviewState.ts` — зеркало серверного предиката
  (`review_status ∈ {confirmed, overridden}` минус анти-накрутка
  `status === "matched_fund" && review_status === "confirmed"`,
  см. `decision_fund_service.py`), перекрёстные комментарии с обеих сторон.
  При `promotableCount === 0` тумблер `disabled` + приглушённое пояснение
  («Фонд пополняют решения, принятые оператором при проверке» — финальный текст
  на реализации). Серверное «отщёлкивание» с `toast.info` остаётся страховкой
  на случай рассинхрона зеркала.
- **`EstimateList`**: ошибка загрузки списка — голый `<p role="alert">` →
  `Alert variant="destructive"` (ножка 3).
- **Ножка 4 — выравнивание:** экраны загрузки данных без скелетона получают его;
  подтверждённый кандидат — `EstimatePage` (`<p>Загрузка…</p>`), остальные места
  инвентаризирует план (у `EstimateList` skeleton уже есть).

Остальные ~15 toast-вызовов соответствуют ножке 2 и не трогаются.

## 5. Адаптивный минимум (цель «не ломается» при ~960px)

- **`ArticleTable`** — `overflow-x-auto` приходит миграцией на `DsTable` (§3).
- **`ReviewGrid`** — внутренняя обёртка с `min-w` (~720–760px, значение
  подбирается на живом гриде), охватывающая **sticky-шапку и виртуализированное
  полотно вместе**, внутри скролл-контейнера — иначе при горизонтальном скролле
  колонки уедут из-под заголовков. Узкое окно даёт горизонтальный скролл
  вместо сжатия `1fr`-колонок.
- **`AppShell` — компактный режим** ниже `md`: `px-6 → px-3`, `gap-5 → gap-3`,
  email в триггере дропдауна заменяется иконкой (`CircleUser`), дропдаун и оба
  таба остаются. Высота шапки не меняется.
- **Живой гейт:** ключевые экраны на 960px и ~760px в браузере с эмуляцией
  ширины (DevTools / браузерный инструментарий агента). Playwright в проект
  не добавляется.

## 6. Плюрализация

- Новый `frontend/src/lib/plural.ts`:
  `pluralizeRu(n: number, forms: [string, string, string]): string` —
  классический mod10/mod100, возвращает форму («замечание/замечания/замечаний»);
  вызывающий составляет строку. Задел под i18n: в этапе 4 вызовы заменяются
  i18next-плюрализацией точечно, места уже параметризованы.
- Применение:
  - `StructureNotice`: `pluralizeZamechanie` удаляется в пользу хелпера;
    «В N строк(ах)…» → «В N строке/строках…»;
  - `ReviewScreen`: «спорная строка / спорные строки / спорных строк» в счётчике
    и диалоге завершения;
  - `TemplateUpload`: «Импорт удалит N строк…».
- Формы «число после двоеточия» («Пропущено строк: N») инвариантны к
  плюрализации и не трогаются.

## 7. Персист аномалий структуры

**Бэкенд:**

- Две колонки в `estimates`: `structure_anomalies` (JSONB, nullable — список
  `{kind, code, name, detail, source_index}`, структура = `StructuralAnomalyOut`)
  и `outline_overrides` (INTEGER NOT NULL DEFAULT 0). Alembic-ревизия
  (автогенерация), ORM-модель синхронно.
- **Момент записи — транзакция ingest** (`service.ingest`, синхронно внутри
  `POST /estimates`, там же, где создаются смета и строки). Доменная сущность
  `Estimate` и порт репозитория расширяются; направление зависимостей не меняется.
- `EstimateDetailOut` += `anomalies: list[StructuralAnomalyOut]` (схема уже
  существует) и `outline_overrides: int`. Легаси-сметы: `NULL` → пустой список
  при чтении. Ответ `POST /estimates` не меняется.

**Фронтенд:**

- `getEstimate` мапит новые поля; `EstimatePage.load()` кладёт их в state
  компонента из первичного `GET` — notice переживает переход processing→open
  без ре-фетча (у свежезагруженной сметы аномалии уже в БД: парсинг завершился
  в POST до навигации).
- Канал navigate-state удаляется целиком: `EstimatesPage` навигирует без
  `state`, чтение `location.state` и комментарии «осознанное ограничение
  Task 7» удаляются. `StructureNotice` не меняется (Collapsible, закрыт по
  умолчанию) — появляется при каждом открытии сметы, включая F5 и прямую ссылку.

## 8. Тесты и верификация

**vitest:**
- `pluralizeRu`: 1/2/5/11/21/111.
- `promotableCount`: 4 случая — unreviewed-confident (0), confirmed (1),
  overridden (1), фонд-хит+confirmed (0).
- `LoginScreen`: при 401 инлайн root-ошибка видима **и toast НЕ вызван**
  (иначе переходный вариант «и там и там» пройдёт тест).
- `DoneScreen`: тумблер disabled + пояснение при `promotableCount === 0`;
  активен при наличии промоутабельных решений.
- `EstimatePage`: аномалии из `GET` при прямом заходе; сценарий
  «upload → processing → poll ready → notice виден» (мок: `GET` со
  `status: "running"` и аномалиями, полл завершается `ready`).

**pytest:**
- ingest персистит аномалии и `outline_overrides`;
- `GET /estimates/{id}` возвращает их; легаси `NULL` → пустой список;
- фейки портов (`tests/fakes.py`) дополняются.

**Живой гейт перед PR:** скриншоты пяти табличных поверхностей (один язык);
логин с неверным паролем; тумблер на смете без операторских решений;
экраны на 960px и ~760px.

## 9. Вне скоупа (осознанно)

- Магическая высота `ReviewGrid` `h-[calc(100vh-184px)]` → TECH_DEBT
  (flex-раскладка отдельной задачей).
- Playwright/e2e как инфраструктура проекта.
- Редизайн токенов MR DS; мобильная версия сверх «не ломается»; светлая тема
  (§7 роадмапа).
- i18n — этап 4 (хелпер плюрализации — только задел).
- Повторная обработка excluded/error-строк, undo — из ранних этапов, не сюда.

## 10. Риски

- **Дрейф зеркала `promotableCount` ↔ `_PROMOTABLE_REVIEW`** при изменении
  правил фонда. Смягчение: перекрёстные комментарии в обоих файлах + юнит-тест
  на 4 случая; серверное «отщёлкивание» остаётся последней линией.
- **`min-w` грида** подбирается вживую — риск «подобрали под один монитор».
  Смягчение: гейт на двух ширинах (960/~760).
- **Структура JSONB-аномалий** замораживается схемой `StructuralAnomalyOut`;
  изменение состава полей аномалий парсера потребует миграции данных или
  толерантного чтения (лишние/отсутствующие ключи игнорируются — Pydantic
  по умолчанию толерантен к лишним, отсутствующие ловим дефолтами).
