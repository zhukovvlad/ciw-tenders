# UX этап 3.6: полоса окружения как справочная поверхность

**Дата:** 2026-07-06
**Статус:** дизайн-решения согласованы (живой прогон этапа 3.5 + верификация по коду), ждёт ревью спеки
**Родитель:** [2026-07-05-ux-stage3-5-queue-ergonomics.md](2026-07-05-ux-stage3-5-queue-ergonomics.md)
(правит визуал полосы, введённой в 3.5 §3 п.2; семантику границы раздела —
[2026-07-05-ux-stage3-5-queue-ergonomics.md](2026-07-05-ux-stage3-5-queue-ergonomics.md) §4 — НЕ трогает).
**Скоуп:** один PR — косметика поверхности `ContextStrip` + одно информационное
изменение (имя присвоенной статьи соседа → `title`). Без изменения поведения,
семантики границы, контракта payload, бэка. Один компонент (`ContextStrip.tsx`)
+ точечно отступ слота в `ReviewCard`, если он живёт там (см. §3 п.4) + тесты.

## 1. Контекст: диагноз живого прогона

Этап 3.5 смержен: полоса контекста живёт слотом внутри `ReviewCard` между
заголовком работы и кандидатами ([ReviewCard.tsx:118](../../../frontend/src/pages/estimate/ReviewCard.tsx#L118)),
граница разделов — по эффективным путям с подписью и подавлением перед
открывашкой. Живой прогон вскрыл визуальную проблему **уровня поверхности**,
не семантики:

- **Полоса и список кандидатов нарисованы одним словарём.** Контейнер полосы —
  `rounded-md border` на общем card-фоне ([ContextStrip.tsx:56](../../../frontend/src/pages/estimate/ContextStrip.tsx#L56)),
  кандидаты — `rounded-md border` того же фона ([ReviewCard.tsx:43](../../../frontend/src/pages/estimate/ReviewCard.tsx#L43)).
  Обведённый прямоугольник рядом с обведёнными прямоугольниками одинаковой ширины
  на одной заливке → окружение читается как «ещё пять кандидатов без номеров».
- **Разрыв полоса↔кандидаты меньше внутристрочного шага полосы.** Зазор задан
  общим `gap-3` флекс-колонки `CardContent` ([ReviewCard.tsx:105](../../../frontend/src/pages/estimate/ReviewCard.tsx#L105)),
  тем же, что и шаг между строками самой полосы (`py-1.5` на строку,
  [ContextStrip.tsx:86](../../../frontend/src/pages/estimate/ContextStrip.tsx#L86)).
  Смены режима «читаю справку → выбираю действие» глаз не чувствует.
- **Правая часть соседа несёт ПОЛНОЕ имя присвоенной статьи.** `rightSide`
  для confirmed-соседа возвращает `${d.code} ${d.name}`
  ([ContextStrip.tsx:33-34](../../../frontend/src/pages/estimate/ContextStrip.tsx#L33-L34)).
  При однородном разделе один и тот же длинный хвост («Устройство гидроизоляции
  фундамента и подземной части здания») повторяется в каждой строке и весит
  больше кандидатов — правый столбец шумит.

**Диагноз:** не хватает различения РОЛЕЙ поверхностей — *справка* против
*действия*. Разносить по разным карточкам нельзя (маршрут «крошка → строка →
окружение → кандидаты» выбран осознанно в 3.5 §2 и остаётся) — различаем
**уровнем поверхности**: полоса становится утопленной тихой панелью, кандидаты
остаются обведёнными кнопками.

## 2. Ключевые решения (и почему)

| Решение | Обоснование |
|---|---|
| **1. Полоса — утопленная поверхность:** контейнер получает заливку `bg-[var(--ds-surface-sunken)]` (токен `--ds-surface-sunken: #110D1C`, темнее card `#16121F` → recessed; [index.css:69](../../../frontend/src/index.css#L69)). Построчных рамок нет (у строк их и не было — [ContextStrip.tsx:85-91](../../../frontend/src/pages/estimate/ContextStrip.tsx#L85-L91) — правило фиксируется регресс-гвардом). Кандидаты не трогаются. | «Залитая тихая панель = справка, обведённые строки = кнопки» — различение ролей *до* чтения. Токен уже несёт роль sunken-поверхности (шапка `AppShell`, `dsHeadRowClass`); не изобретаем цвет. Литерал не заводим — токен через CSS-var (см. §3 п.1 о `dsHeadRowClass`). |
| **2. Подпись панели «Окружение в смете»** — микрокегль, uppercase, muted, первым элементом внутри залитого контейнера. Тот же типографический словарь, что подпись разделителя «Раздел — …»: `text-[11px] tracking-wide text-muted-foreground uppercase` ([ContextStrip.tsx:75](../../../frontend/src/pages/estimate/ContextStrip.tsx#L75)). | Панель без имени — просто прямоугольник; подпись объявляет «это справка об окружении», а не список действий. Общий словарь с подписью раздела держит полосу единой типографической системой. |
| **3. Правая часть присвоенного соседа — код статьи моноширинным («→ 3.2»)**, полное имя — в нативном `title`. Меняется только confirmed-ветвь `rightSide` ([ContextStrip.tsx:33-34](../../../frontend/src/pages/estimate/ContextStrip.tsx#L33-L34)); статусные подписи неприсвоенных соседей (`statusLabel`: «Требует проверки» / «Контекст» / «В обработке» / «Нет совпадения») — без изменений. | **Осознанный trade-off:** `title` недоступен с клавиатуры и тача. Принято: оператору для сигнала «сосед присвоен, вон куда» достаточно кода; согласованность соседей («все ушли в 3.2») кодами виднее, чем повторяющимися длинными именами. Пересмотр (тултип-компонент) — только по жалобе операторов (§5). |
| **4. Воздух:** отступ полоса↔кандидаты больше внутристрочного шага полосы. Живёт ниже полосы (добавочный `mb-*` на корне `ContextStrip` поверх флекс-`gap-3`, либо на слоте в `ReviewCard`). | Пауза на смене режима «читаю → выбираю». Сейчас зазор равен внутреннему шагу → границы режимов нет. Добавочный отступ *под* полосой (не над) не трогает разрыв заголовок-работы↔полоса. |
| **5. Активная строка полосы:** лёгкий тинт (уже есть — [ContextStrip.tsx:88](../../../frontend/src/pages/estimate/ContextStrip.tsx#L88)) + акцентная кромка слева `border-l`; маркер «вы здесь» (`ArrowLeft`, [ContextStrip.tsx:99](../../../frontend/src/pages/estimate/ContextStrip.tsx#L99)) сохраняется. | На утопленном фоне тинт один читается слабее, чем на card; кромка слева даёт «якорь взгляда» без превращения строки в кнопку (кромка ≠ полная рамка — не словарь кандидатов). Маркер из 3.5 несёт «это решаемая прямо сейчас», не дублируется. |

**Что осознанно НЕ меняется** (границы правки): семантика границы раздела
(эффективные пути, предикат открывашки, подавление самообъявления, стилизация
открывашки `font-medium`, страж независимости от `MatchStatus`) — вся логика 3.5
§4 остаётся байт-в-байт. Приглушение excluded/pending (`opacity-60`) — тоже.

## 3. Правки (один PR, поведение не меняется)

Все — в `ContextStrip.tsx`, кроме п.4 (возможно точечно `ReviewCard`).

1. **Заливка контейнера** ([ContextStrip.tsx:56](../../../frontend/src/pages/estimate/ContextStrip.tsx#L56)):
   к текущему `rounded-md border text-xs` + `dsHairline` добавить заливку
   sunken-токеном. Токен уже экспонирован в DS константой
   `dsHeadRowClass = "bg-[var(--ds-surface-sunken)]"` ([ds-table.tsx:24](../../../frontend/src/components/common/ds-table.tsx#L24)),
   но её имя семантично для шапки таблицы. Скоуп PR — `ContextStrip`, поэтому
   заливку добавить как `bg-[var(--ds-surface-sunken)]` инлайн (переиспользуем
   **токен**, не литерал-класс — единый источник цвета сохранён). Внешний
   hairline-border может остаться: он тоньше `border-border` кандидатов
   (`--ds-hairline` #1C1830 против #2A2640) — заливка, не рамка, несёт различение
   роли. *Необязательный follow-up (вне этого PR):* завести в `ds-table`
   именованную `dsSurfaceSunken` и переиспользовать в обоих местах — если ревьюер
   захочет дедуп литерала токена.
2. **Подпись панели**: первым дочерним элементом контейнера (до `win.map`) —
   `<div>` с текстом «Окружение в смете», классы из решения #2 (тот же словарь,
   что подпись разделителя). Отступы — как у подписи разделителя (`px-3`),
   чтобы не разъезжалось со строками.
3. **Right-side присвоенного соседа** ([ContextStrip.tsx:30-36](../../../frontend/src/pages/estimate/ContextStrip.tsx#L30-L36),
   [:104-106](../../../frontend/src/pages/estimate/ContextStrip.tsx#L104-L106)):
   для confirmed показывать `→ {d.code}` (моноширинно, как `section_code` слева
   — [ContextStrip.tsx:93](../../../frontend/src/pages/estimate/ContextStrip.tsx#L93)),
   `title={`${d.code} ${d.name}`}` на этом же `<span>`. Неприсвоенные (ветвь
   `statusLabel`) — без изменений, без `title`. Форму `Decision.confirmed`
   (code/name) сверять по [types.ts](../../../frontend/src/lib/types.ts), как
   помечено в комментарии `rightSide`.
4. **Воздух под полосой** (решение #4): добавочный нижний отступ поверх
   флекс-`gap-3`. Рекомендация — `mb-*` на корне `ContextStrip` (изменение
   локализовано в компоненте, `ReviewCard` не трогается; в флексе margin+gap
   складываются, отступ *только под* полосой — что и нужно). Величина
   подбирается вживую так, чтобы разрыв полоса↔кандидаты был заметно больше
   внутреннего шага строк (`py-1.5`). Если удобнее держать в слоте — точечный
   класс на `{contextStrip}` в [ReviewCard.tsx:118](../../../frontend/src/pages/estimate/ReviewCard.tsx#L118)
   (в пределах скоупа).
5. **Кромка активной строки** ([ContextStrip.tsx:81-91](../../../frontend/src/pages/estimate/ContextStrip.tsx#L81-L91)):
   базовую кромку `border-l-2 border-transparent` навесить на **каждую** строку,
   активная лишь перекрашивает тон (`--primary`/`--ds-border-strong` — финальный
   тон на реализации, читаемость на sunken проверить). Резервирование ширины на
   всех строках убирает горизонтальный «дёрг» контента при переходе активной:
   `border-l` только у активной сместил бы её контент на толщину кромки
   относительно соседей — на плотной панели строки прыгали бы на 2px при
   движении очереди. Тинт и маркер `ArrowLeft` не трогать. `data-active` уже
   стоит на строке с 3.5 ([ContextStrip.tsx:84](../../../frontend/src/pages/estimate/ContextStrip.tsx#L84))
   — тест кромки (§4) опирается на него, новый атрибут не вводим. Кромка не
   должна визуально смыкать строку в кнопку — только левая грань.

## 4. Тесты и верификация

**Затрагиваемые тесты 3.5 (`ContextStrip.test.tsx`) — семантика НЕ меняется,
эти тесты остаются зелёными как есть, без правок:**

- окно ±2, приглушение excluded (`opacity-60`), активная помечена, разделитель
  на границе, страж независимости от `MatchStatus`, парный тест самообъявления
  (`font-medium` ∧ подавление разделителя), открывашка на краю окна, «две
  границы», «путь укоротился» — все проверяют **семантику границы/окна**, её не
  трогаем. Ни один не ассертит контент right-side у confirmed-строки → правка
  §3 п.3 их не задевает. (Фикстуры `SAME_LEAF_ROWS`/`SIBLING_ROWS` —
  `needs_review` ([ContextStrip.test.tsx:82-104](../../../frontend/src/pages/estimate/ContextStrip.test.tsx#L82-L104))
  → `initReview` даёт `pending` → их right-side это статусная подпись
  `statusLabel`, которую §3 п.3 не касается; ассерты идут по тексту разделителя
  «Раздел — …», не по right-side.)
- Тест «активная строка — маркер, не статус» (`textContent` не содержит `→`)
  остаётся валиден: активная по-прежнему рисует `ArrowLeft`, не right-side;
  добавленный `border-l` на его ассерт не влияет.

**Новые тесты (`ContextStrip.test.tsx`) — презентационные, литералы брать из
реализации, не из спеки:**

- **Подпись панели рендерится**: `screen.getByText(/Окружение в смете/i)`
  присутствует.
- **Строки полосы не несут словаря кандидата** (регресс-гвард роли поверхности):
  для `[data-row]` — `className` не содержит видимого фрейма кандидата
  (`rounded-md` + `border-border`). Базовая кромка `border-l-2 border-transparent`
  (и перекрашенный тон активной) допустимы: гвард проверяет ТОН/словарь, а не
  наличие подстроки `border` — иначе ложно упал бы на резервной кромке.
- **Right-side присвоенного соседа = код + title**: сосед с confirmed-решением
  (pick/manual/confirm) → его `[data-row]` right-side содержит `d.code` и НЕ
  содержит `d.name`; `title` на элементе = полное `«{code} {name}»`.
- **Активная строка**: `[data-active]`-строка (атрибут с 3.5,
  [ContextStrip.tsx:84](../../../frontend/src/pages/estimate/ContextStrip.tsx#L84))
  несёт перекрашенный тон кромки (не `border-transparent`) и тинт; маркер
  `getByLabelText("вы здесь")` сохранён.

**Живой гейт:**

- **Смета 16** и **смета с однородным разделом** (скриншот из 3.5,
  «С5_MIND_Этап 1») — до/после:
  - полоса читается как *справка* (утопленная панель), а не «ещё кандидаты»;
  - правый столбец не шумит (коды вместо повторяющихся длинных имён);
  - разделитель раздела и стилизация открывашки (`font-medium`) **различимы на
    утопленной заливке** — отдельно проверить контраст `font-medium` открывашки
    и `text-muted-foreground` (section_code / статусы) на `#110D1C`;
  - разрыв полоса↔кандидаты ощущается паузой «читаю → выбираю»;
  - активная строка не выглядит кнопкой (кромка + тинт, не рамка).

## 5. Вне скоупа (осознанно)

- Тултип-компонент вместо нативного `title` — пересмотреть, только если появится
  жалоба операторов на недоступность полного имени соседа с клавиатуры/тача
  (trade-off решения #3).
- Виртуализация / расширение окна полосы, любой интерактив в полосе (клик,
  фокус, навигация) — полоса остаётся справочной, некликабельной.
- Правки словаря кандидатов и остальной карточки (`ReviewCard` — только отступ
  слота, если §3 п.4 живёт там).
- Дедуп токена sunken в именованную `ds-table`-константу — необязательный
  follow-up (§3 п.1), не блокирует PR.

## 6. Риски

- **Контраст на утопленной заливке.** `#110D1C` темнее card → приглушённые
  тона (`text-muted-foreground` #76728C) и hairline теряют контраст. Смягчение:
  явная проверка на живом гейте (§4), при провале — поднять тон подписей/кромки.
- **`mb-*` подбирается вживую** (как `max-w` в 3.5) — риск «подобрали под один
  случай». Смягчение: гейт на однородном разделе, где шаг строк максимально
  плотный (много одноимённых соседей).
- **Регресс-гвард роли поверхности.** Базовая кромка `border-l-2 border-transparent`
  на всех строках (§3 п.5) → гвард проверяет ТОН/словарь кандидата (`rounded-md`
  + `border-border`), а не наличие подстроки `border` в классе, иначе ложно упал
  бы на резервной кромке. Зафиксировано в формулировке теста (§4).
