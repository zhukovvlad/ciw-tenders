## Что сделано

Вторая половина этапа 2: экран ревью, работающий на тысячах строк. Дефолтный режим —
«Очередь» (карточка решения на первой нерешённой спорной строке + полоса контекста ±2 +
хоткеи `1–3`/`0`/`Enter`/`N`/`←`); таблица — read-only виртуализированный грид под
`?view=grid`; терминальный экран пустой очереди; undo-стек всех коммитов сессии; память
карточки «откуда пришла». Плюс серверный guard «excluded не решается» и честная шапка
«спорных решено X из Y» (excluded больше не считается строкой СМР).

## Архитектура слоёв

Редьюсер `reviewState` **не тронут** — решения остаются зеркалом сервера. Поверх него новый
сессионный in-memory слой [useReviewQueue](../../frontend/src/lib/useReviewQueue.ts):
порядок спорных по `sourceIndex`, skip-в-хвост (`N`), undo-стек, происхождение активной
карточки (`flow`/`grid`/`undo`), возврат упавшей строки в голову очереди. После F5 порядок
исходный, стек пуст — by design (сессионная эфемерность, сервер главнее).

Ключевые инварианты слоя (запинованы юнитами):
- **`sessionDecided: Set<number>`** — «решено в этой сессии» оптимистично, независимо от
  ответа PATCH. Именно Set, а не членство в undo-стеке: стек — мультимножество (двойной
  коммит одной строки без промежуточного `←` даёт два вхождения, `commitFailed` снимает
  только последнее) — подмена Set'а стеком молча теряла проваленное решение; поймано на
  ревью задачи, закрыто регрессионным тестом «двойной коммит».
- **`activeRowRef` пишется в фазе рендера** (scoped `eslint-disable react-hooks/refs` с
  обоснованием): `commitFailed` зовётся из `.then` PATCH-промиса — микротаск обгоняет
  пассивный `useEffect`, и ref, обновляемый эффектом, был бы stale ровно в момент вызова
  (оператора выдёргивало бы назад на упавшую строку — запрещено спекой §3a). Пин-тест
  «STALE CLOSURE» + живой сценарий в браузерном гейте.
- Guard skip: `N` на ad-hoc строке (confident/фонд, открытой из грида) не загрязняет
  порядок спорных — карточка закрывается по происхождению.

## Карточка, полоса, грид, терминал

- [ReviewCard](../../frontend/src/pages/estimate/ReviewCard.tsx) — единственная поверхность
  решения (спека §3b): крошка сметы + работа полным текстом, рекомендация «AI»/«Из фонда»
  (гейт синтетической рекомендации перенесён из `ReviewRow` как есть), кандидаты `1–3`,
  серверный поиск на shadcn `Command` (`shouldFilter={false}`, дебаунс-паттерн `reqIdRef`
  из старой таблицы), «Оставить без пары» (`0`), постоянная легенда клавиш с приглушением
  неактивных. Error-строки: текст `match_error`, только поиск и «без пары». Хоткеи живут
  НЕ в карточке — их вешает экран.
- [CrumbTrail](../../frontend/src/components/estimate/CrumbTrail.tsx) — крошка со средним
  эллипсисом (>3 уровней → первый › … › два последних, полная цепочка в `title`).
  Осознанное отступление от shadcn-first: примитив `Breadcrumb` — навигационный
  (`<nav>`-ландмарк), а наша крошка — декоративная подпись, повторяющаяся десятками на
  экране; `breadcrumb.tsx` не вендорился (обоснование в плане).
- [ContextStrip](../../frontend/src/pages/estimate/ContextStrip.tsx) — ±2 соседа по
  `sourceIndex` среди всех строк (excluded приглушены), разделители на границах
  верхнеуровневых разделов. Без виртуализации — окно константное (спека §5).
- [ReviewGrid](../../frontend/src/pages/estimate/ReviewGrid.tsx) — div-разметка в языке
  shadcn Table (роли `table`/`row`/`cell`), фиксированная высота строки `ROW_H = 64`,
  sticky-шапка, чипы-фильтры переехали сюда (действуют только в гриде). Кликабельность:
  excluded/pending приглушены и некликабельны; `onOpenRow === undefined` ⇒ read-only.
- [QueueDone](../../frontend/src/pages/estimate/QueueDone.tsx) — терминальный экран
  (сводка из `progress` + счёт по `decisionFor`, CTA «Завершить проверку» без диалога,
  «Посмотреть таблицу»).
- [ReviewScreen](../../frontend/src/pages/estimate/ReviewScreen.tsx) — шелл: режим из URL
  (`?view=grid`, F5/back работают через URL), ручной уход в грид зовёт `deselect`
  (возврат в очередь — поток, а не давно открытая карточка), единая точка коммита.
  Старая аккордеонная таблица (`ReviewRow.tsx`) удалена вместе с тестами.

## Выбор @tanstack/react-virtual

Новая зависимость (v3, ~4 КБ gzip, без транзитивных): headless (грид остаётся в визуальном
языке DS), есть `scrollToIndex`/`scrollToOffset` (память позиции «к таблице» и скролл к
активной), фиксированная высота = `estimateSize` без measure-цикла, тестируется в jsdom.
Отвергнуты `react-window` (навязывает компоненты — sticky-шапка «через не могу»),
`react-virtuoso` (тяжелее, стили сложнее подчинить DS), ручная виртуализация
(переизобретение overscan/scrollToIndex). Нюанс jsdom: дефолтный `observeElementRect`
синхронно замеряет 0×0 и клоббает `initialRect` — в гриде тест-only ветка с кастомным
`observeElementRect` (включается только пропом `initialRect`; прод-путь не тронут).

## Контракт onReview и ошибка PATCH

`EstimatePage.handleReview` возвращает `Promise<boolean>`: `true` — синк строки с сервера,
`false` — вызывающий уже сделал `reopen` (откат оптимистичного решения) + toast с именем
строки (текст нейтральный: «возвращена в начало очереди» была бы ложью для confident-строки
из грида). Экран по `false` зовёт `queue.commitFailed(n)`: строка вон из undo-стека, в
голову очереди (станет следующей), активную не выдёргивает.

## Бэк: guard excluded + `_collect_article_ids`

`PATCH .../review` на excluded-строке теперь 409 (`RowNotReviewableError` в домене, guard в
[estimate_review_service.py](../../backend/app/services/estimate_review_service.py) после
guard'а pending) — контракт «excluded не решается» держит и сервер, не только клиент
(закрывает рекомендацию финального ревью PR-A). Дубль set-comprehension сборщиков id статей
в двух роутах заменён модульным хелпером `_collect_article_ids`
([routes/estimates.py](../../backend/app/api/routes/estimates.py)) — тоже долг ревью PR-A.
