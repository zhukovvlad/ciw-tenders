## Табличный язык: `ds-table`

Новый модуль [ds-table.tsx](../../frontend/src/components/common/ds-table.tsx) —
единственный источник табличного стиля: тонкие обёртки над вендорным
`components/ui/table.tsx` (`DsTable*`) + классы-константы (`dsHeadCellClass`,
`dsCellClass`, `dsHairline`, `dsHeadRowClass`) для поверхностей, которые не могут быть
`<table>` (виртуализированный `ReviewGrid`, `ContextStrip`). Ключевой приём —
`DsTableRow`'s `interactive?: boolean`: неинтерактивная строка гасит вендорный
`hover:bg-muted/50` через `hover:bg-transparent` (tailwind-merge побеждает по паре
модификатор+группа классов, порядок в `cn()` решает). `EstimateList`, `StructureNotice`,
`ArticleTable` (сырой `<table>` → `DsTable*`, `overflow-x` бесплатно), `ReviewGrid`,
`ContextStrip` — все пять поверхностей теперь на одном канону: uppercase-шапка,
единый фон (`--ds-surface-sunken`), единая граница (`--ds-hairline`), hover только там,
где клик что-то делает.

`ReviewGrid` получил `min-w-[720px]`-обёртку вокруг sticky-шапки и виртуализированного
полотна **внутри одного** скролл-контейнера — раньше при горизонтальном скролле узкого
окна колонки могли уехать из-под заголовков, теперь шапка и тело гарантированно делят
один offset. Магическая высота грида (`h-[calc(100vh-184px)]`) задокументирована в
[TECH_DEBT.md](../TECH_DEBT.md) — перевод на flex-раскладку отложен (компактная шапка
Task 11 высоту не меняла, `py-3` сохранён намеренно).

## Политика фидбека (4 ножки)

- **Ножка 1 (логин):** `sonner`-toast на ошибке входа заменён на инлайн `role="alert"`
  под кнопкой через `form.setError("root", …)` — shadcn `FormMessage` привязан к
  `FormField`-контексту и root-ошибку сам не рендерит, поэтому вывод ручной.
- **Ножки 3-4 (загрузка):** `EstimateList` на ошибке — `Alert variant="destructive"`
  вместо голого текста; `EstimatePage` на `meta.kind === "loading"` — три `Skeleton`
  вместо «Загрузка…». Инвентаризация показала, что `ArticlesPage` и сам `EstimateList`
  на загрузке уже используют `Skeleton` — пробел был только в `EstimatePage`.
- **Тумблер фонда:** новый хелпер `promotableCount()` в `reviewState.ts` — точное
  зеркало серверного предиката `_PROMOTABLE_REVIEW` из
  [decision_fund_service.py](../../backend/app/services/decision_fund_service.py),
  включая анти-накрутку (подтверждённый фонд-хит не промоутабелен — фонд не
  рекрутируется из самого себя). `blockedByEmpty = promotable === 0 && !inFund`:
  тумблер выключен с пояснением только когда операторских решений нет И смета ещё не
  в фонде — reverse-флоу (снять уже эталонную смету) остаётся доступным всегда.

## Адаптив

`AppShell` ниже `md`: email пользователя скрывается (`hidden md:inline`), вместо него
иконка `CircleUser`; горизонтальные отступы шапки уменьшаются (`gap-3`/`px-3` →
`md:gap-5`/`md:px-6`), вертикальный `py-3` не тронут (от него зависит оффсет грида).
Ревью первого раунда поймало реальный дефект: в живом браузере (не в jsdom, который не
грузит CSS) `email`-спан реально уходит в `display:none`, а иконки `lucide-react` без
детей автоматически получают `aria-hidden`, — итог: у триггера меню пользователя
пропадало accessible name ниже `md` (WCAG 4.1.2). Пофикшено `aria-label={user.email}`
на `DropdownMenuTrigger` + тест, проверяющий атрибут напрямую (а не через
jsdom-артефакт отсутствия CSS).

## Плюрализация

[pluralizeRu(n, [one, few, many])](../../frontend/src/lib/plural.ts) — стандартное
русское mod10/mod100-правило. Применена в `StructureNotice` (заголовок и агрегатная
строка «в N строке/строках/строках»), диалоге завершения ревью («N спорная
строка/спорные строки/спорных строк»), предупреждении об импорте шаблона справочника.
Задел под этап 4 (i18n) — вызовы уже параметризованы под будущую замену на
i18next-плюрализацию.

## Персист аномалий структуры

Раньше аномалии парсинга (`ParsedEstimate.anomalies`/`.outline_overrides`) уходили на
фронт только один раз, через `navigate(..., { state })` после аплоада — F5 или прямая
ссылка их теряли. Теперь `estimates.structure_anomalies` (JSONB, nullable) и
`outline_overrides` (Integer, `server_default 0`) — миграция `0009`, чтение в
`_to_entity()` толерантно (`m.structure_anomalies or []`, `.get()` по ключам — тот же
паттерн, что и у `candidates`). `GET /estimates/{id}` отдаёт оба поля; фронт
(`EstimatePage`) больше не читает `location.state` — `notice` сеется из ответа `GET`
внутри `load()`, переживает переход `processing → open` без ре-фетча.
